# 민들레 마을 — 게임 설계 문서 (GDD v0.1)

> 상태: 초안 · 결정된 사항은 ✅, 아직 정할 사항은 ❓로 표시

## 0. 확정된 전제

| 항목 | 결정 |
|---|---|
| 핵심 재미 | ✅ **꾸미기·건설** (농사, 관계, 탐험은 이를 받쳐 주는 보조 시스템) |
| 플랫폼 | ✅ PC(Steam) 먼저 출시하고 모바일(iOS·Android)은 이후에 이식 |
| 엔진 | ✅ Godot 4 (무료, 2D 픽셀 게임에 강함, PC·모바일 동시 빌드) |
| 그래픽 | ✅ 상용 픽셀아트 에셋 팩 (16×16 타일 기준) |
| 목표 | ✅ 상업 출시 |

기존 웹 프로토타입(`farm-game/`)은 **기획 검증용 시제품**으로만 쓰고, 본 게임은 Godot으로 새로 만든다.

---

## 1. 컨셉

**한 줄 소개:** 시들어 버린 골짜기에 이사 와서, 원하는 대로 짓고 꾸민 만큼 마을이 되살아나는 힐링 건설 농장 게임.

**차별점 (스타듀밸리와 다른 점)**
- 스타듀밸리에서 꾸미기는 "덤"이지만, 이 게임에서는 **꾸미기가 곧 진행**이다.
- 플레이어가 꾸민 공간의 **매력도**를 보고 새 주민이 이사 온다. 주민이 늘면 상점, 레시피, 새 지역이 열린다.
- 농장, 집 안, 마을 광장까지 **어디든 자유롭게 배치하고 옮길 수 있다.**

**참고 게임:** 스타듀밸리(하루 루프), 동물의 숲(주민 유치, 꾸미기), 딩컴(마을 건설), 코랄 아일랜드

## 2. 디자인 기둥 (모든 기능은 이 셋 중 하나 이상을 강화해야 함)

1. **어디든, 무엇이든 놓는다** — 배치 제약은 최소한으로 두고, 옮기기·되돌리기는 언제나 쉽게.
2. **꾸민 것이 의미가 있다** — 장식은 보기 좋은 데서 끝나지 않고 매력도, 주민, 작물, 동물에 영향을 준다.
3. **느긋한 하루** — 벌칙은 약하게. 실패해도 잃는 건 적고, 매일 작은 성취를 느끼게.

## 3. 게임 루프

```
[하루 루프]   채집·농사·낚시로 재료 확보 → 제작 → 배치·꾸미기 → 출하·판매로 돈 → 잠 (저장)
[주간 루프]   구역 매력도 달성 → 주민 이사 요청 → 주민 입주 → 새 상점·레시피 해금
[계절 루프]   계절 한정 재료·장식 → 마을 축제(꾸미기 콘테스트) → 새 지역 개방
```

## 4. 핵심 시스템

### 4.1 건설·배치 시스템 ★ 게임의 심장, 가장 먼저 만들고 검증
- **그리드:** 16×16 타일 격자. 물건마다 차지하는 칸이 있다 (1×1, 2×1, 3×3 등).
- **레이어:** 바닥(길·카펫) / 오브젝트(가구·울타리) / 벽걸이 / 지붕·건물. 레이어가 다르면 겹쳐 놓을 수 있다.
- **조작:** 들기 → 회전(4방향) → 놓기, 이동, 회수, **되돌리기(Undo)**, 여러 개 한꺼번에 선택.
- **꾸미기 모드:** 시간을 멈추고 화면을 위에서 내려다보는 전용 편집 모드 (모바일에서 특히 중요).
- **지형 편집:** 길 깔기, 연못 파기·메우기, 꽃밭·잔디 칠하기 (브러시 방식).
- **건물:** 헛간, 닭장, 온실, 주민 집. 설계도를 사서 부지를 정하면 며칠 뒤 완공되고, 나중에 통째로 옮길 수 있다.
- **실내:** 내 집 벽지, 바닥, 가구 배치. 집을 증축하면 방이 늘어난다.

### 4.2 매력도 시스템 (꾸미기 ↔ 진행을 잇는 장치)
- 맵을 구역으로 나누고, 구역마다 장식이 매력도 점수를 준다.
- 점수 태그: `자연` `편안함` `조명` `물가` `먹거리` `놀이`
- 예) 벤치 = 편안함 +2, 가로등 = 조명 +3, 같은 물건을 반복하면 점수가 점점 줄어들어 다양성을 유도한다.
- 주민마다 좋아하는 태그가 달라서, 조건을 채운 구역이 생기면 그 주민의 이사 요청이 온다.

### 4.3 농사 (보조)
- 밭 갈기 → 심기 → 물 주기 → 수확. 계절 작물, 다시 열리는 작물, 스프링클러.
- 꾸미기 연계: 허수아비는 까마귀를 막고, 벌통 근처 꽃은 꿀 품질을 올리는 식으로 장식이 기능도 한다.

### 4.4 주민·관계
- 출시 기준 주민 10명. 각자 좋아하는 태그, 선물 취향, 하트 이벤트 3개.
- 주민에게 **집 꾸미기 의뢰**를 받는 퀘스트가 핵심 콘텐츠다 (예: "조명이 많은 아늑한 방").
- ❓ 연애·결혼은 넣을지 나중에 결정 (출시 범위를 크게 늘림).

### 4.5 채집·제작·경제
- 재료: 목재, 돌, 섬유, 광석, 꽃, 계절 재료.
- 제작대 등급(작업대 → 목공소 → 공방)이 올라가면 만들 수 있는 가구가 늘어난다.
- 돈 사용처: 씨앗, 설계도, 건물, 증축, 가구 상점(날마다 바뀌는 품목 → 매일 접속할 이유).

### 4.6 가벼운 탐험 (보조)
- 낚시(도감), 채석장·동굴(재료 채집 위주, 전투는 없거나 최소한).

### 4.7 시간·계절
- 하루 약 14분(실제 시간), 계절당 28일, 사계절. 날씨(맑음, 비, 눈, 폭풍).
- 새벽 2시에 기절해도 벌칙은 약하게 (기둥 3).

## 5. 출시 콘텐츠 범위 (v1.0 목표)

| 항목 | 수량 |
|---|---|
| 지역 | 농장, 마을 광장, 숲, 해변, 채석장 (5곳) |
| 배치 가능한 물건 | 가구·장식 약 200종, 건물 8종 |
| 작물 / 물고기 | 작물 24종 / 물고기 30종 |
| 주민 | 10명 (하트 이벤트 각 3개) |
| 축제 | 계절마다 1개 (4개) |
| 플레이 분량 | 1년차 완주 약 30~40시간 |

## 6. 기술 설계 (Godot 4)

### 6.1 폴더 구조
```
game/
├─ project.godot
├─ autoload/        # 전역 관리자
│   ├─ GameClock.gd     # 시간·날짜·계절, 신호(signal) 발송
│   ├─ SaveManager.gd   # 저장·불러오기, 버전 관리
│   ├─ Inventory.gd
│   └─ EventBus.gd      # 시스템끼리 느슨하게 연결
├─ data/            # 아이템·작물·주민을 Resource(.tres)로 정의 (코드 수정 없이 콘텐츠 추가)
├─ systems/
│   ├─ placement/       # 그리드, 배치 규칙, Undo 스택
│   ├─ appeal/          # 매력도 계산
│   ├─ farming/
│   └─ npc/             # 일정표, 길찾기, 대화
├─ scenes/          # 지역별 맵 (TileMapLayer + Y-정렬)
├─ ui/
└─ assets/          # 구매한 에셋 팩 (원본은 따로 보관)
```

### 6.2 주요 원칙
- **데이터 주도:** 아이템 하나 추가 = `.tres` 파일 하나 추가. 코드는 건드리지 않는다.
- **배치 데이터 모델:** `구역 → 레이어 → {칸 좌표: 물건ID, 회전, 상태}`. 저장 파일도 이 구조를 그대로 쓴다.
- **저장:** JSON + 버전 번호. 업데이트해도 예전 세이브를 변환해서 읽을 수 있게 한다 (출시 게임 필수).
- **입력 추상화:** 키보드·마우스, 게임패드, 터치를 같은 "행동"으로 연결 → 모바일 이식 비용을 줄인다.
- **다국어:** 처음부터 모든 문장을 번역 표(CSV)로 관리한다 (한국어·영어 동시 출시 대비).
- **성능:** 모바일 기준 한 화면에 물건 500개 이상에서도 60fps (배치 게임은 물건 수가 많아짐).

## 7. 아트 계획

### 7.1 에셋 팩 선정 기준
1. **상업적 이용 허용** 라이선스 (필수, 구매 전 원문 확인)
2. 16×16 타일, 농장 + 실내 가구 + 캐릭터가 **한 작가의 한 시리즈**로 갖춰져 있을 것 (섞으면 화풍이 깨짐)
3. 캐릭터 4방향 걷기 + 도구 동작, 계절별 타일 포함
4. 가구 종류가 많을 것 (꾸미기 게임이라 가장 중요)

❓ 후보: Mana Seed 시리즈(Seliel the Shaper), Sprout Lands(Cup Nooodle) 등. 라이선스와 가구 수량을 비교한 뒤 결정.

### 7.2 에셋 팩으로 부족할 부분
- 주민 초상화, 게임 고유 건물·로고 → 같은 화풍으로 외주 (예산 ❓)
- 팩에 없는 가구 → 팩의 색 팔레트를 그대로 써서 보충

## 8. 개발 로드맵

| 단계 | 목표 | 완료 기준 |
|---|---|---|
| **M0 프로토타입** | 배치 시스템 검증 | 들기·회전·놓기·Undo·저장이 되고, 30분 꾸며도 재미있는가 |
| **M1 수직 단면** | 봄 한 계절 완성 | 농사 + 꾸미기 + 매력도 + 주민 2명 입주까지 한 바퀴 |
| **M2 콘텐츠** | 사계절, 주민 10명 | 1년차 완주 가능 |
| **M3 알파** | 스팀 페이지·찜하기 모으기, 외부 테스트 | 테스터 피드백 반영 |
| **M4 출시** | PC 출시 → 모바일 이식 | 치명적 버그 0, 세이브 호환 |

> **가장 큰 위험은 "배치가 재미없거나 불편한 것"**이다. 그래서 M0에서 배치만 먼저 만들어 검증한다.

## 9. 위험 요소

| 위험 | 대응 |
|---|---|
| 범위 폭발 (출시 게임의 가장 흔한 실패 원인) | 5장 수량을 상한으로 고정, 추가 기능은 출시 후 업데이트로 |
