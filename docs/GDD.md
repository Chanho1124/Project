# 가칭 「민들레 대륙」 — 게임 설계 문서 (GDD v0.2)

> 상태: 초안 · ✅ 확정 · ❓ 결정 필요
> v0.1(꾸미기 중심 농장 게임)에서 **2D 픽셀 오픈월드 샌드박스**로 방향 전환

| 항목 | 결정 |

| 겉모습 | ✅ 스타듀밸리 같은 **2D 탑다운 픽셀아트** (16×16 타일, 에셋 팩 사용) |
| 게임성 | ✅ **듀랑고 같은 높은 자유도의 샌드박스**: 생존, 채집, 제작, 건설, 사냥·길들이기, 거래. 정해진 길 없이 플레이어가 스스로 할 일을 정함 |

## 1. "유저가 원하는 건 다 할 수 있게"를 설계로 바꾸기

말 그대로 "모든 것"을 하나하나 만들 수는 없다. 자유도 높은 게임들(듀랑고, 마인크래프트, 림월드, 돈스타브)의 공통 비결은 **기능을 많이 만드는 것이 아니라, 서로 맞물리는 규칙(시스템)을 만드는 것**이다.

- ❌ "다리 만들기 기능"을 따로 만든다.
- ✅ "나무 판자는 물 위에 깔 수 있다" + "판자 위는 걸을 수 있다"는 규칙만 만든다. 그러면 플레이어가 다리도, 수상 가옥도, 뗏목 선착장도 **알아서** 만든다.

이렇게 규칙끼리 만나서 개발자가 예상하지 못한 플레이가 생기는 것을 **창발성(emergence)**이라 한다. 이 게임의 모든 설계는 이 원칙을 따른다.

## 2. 컨셉

**한 줄 소개:** 낯선 대륙에 맨몸으로 떨어진 사람들이 살아남고, 집을 짓고, 마을을 세우고, 저마다의 방식으로 사는 2D 픽셀 샌드박스.

**플레이어가 될 수 있는 것 (예시, 강제 아님)**
- 깊은 숲을 탐험하는 사냥꾼, 공룡·동물 조련사
- 마을 광장에서 가게를 여는 요리사·재단사·대장장이
- 큰 저택과 정원을 꾸미는 건축가
- 여러 섬을 오가며 물건을 사고파는 상인
- 이 모든 걸 조금씩 하는 사람

## 3. 디자인 기둥

1. **규칙은 단순하게, 조합은 무한하게** — 새 기능보다 기존 규칙과 잘 맞물리는 규칙을 먼저 만든다.
2. **직업은 선택이 아니라 행동의 결과** — 클래스 선택 없이, 하는 만큼 그 기술이 오른다.
3. **세상이 플레이어의 흔적을 기억한다** — 베어 낸 나무, 지은 집, 길들인 동물이 그대로 남는다.
4. **살아남기는 긴장감을 줄 만큼만** — 생존은 동기를 주는 장치이지 벌칙이 아니다.

## 4. 세계 구조 (듀랑고의 좋은 점을 가져오기)

| 구역 | 성격 | 역할 |
|---|---|---|
| **정착지 대륙** | 고정된 맵, 안전함 | 집·마을을 짓는 곳. 플레이어의 흔적이 영구히 남음 |
| **탐험 섬** | **절차적 생성**(매번 새로 만들어짐), 위험함, 일정 기간 뒤 사라짐 | 희귀 재료, 사냥, 탐험. 콘텐츠가 바닥나지 않게 하는 핵심 |
| **특수 지역** | 화산, 설원, 늪, 유적 | 환경 적응(더위·추위) 장비가 있어야 들어갈 수 있음 |

> 듀랑고의 "불안정 섬 / 안정 섬" 구조를 참고했다. 매번 새로운 탐험지가 생기니 개발자가 맵을 계속 그리지 않아도 된다.

## 5. 핵심 시스템

### 5.1 생존
- 수치: 배고픔, 기력, 체온, 체력. 날씨·지역·옷에 따라 체온이 바뀐다.
- 음식은 요리할수록 효과가 좋아진다 (재료 조합 → 요리 레시피 발견).
- 죽으면 그 자리에 가방을 떨구고 정착지에서 부활한다 (벌칙은 가볍게, 기둥 4).

### 5.2 기술 (직업) — 하는 만큼 오른다
| 계열 | 기술 예시 |
|---|---|
| 채집 | 벌목, 채광, 채집, 낚시, 사냥 |
| 생산 | 요리, 재봉, 대장일, 목공, 석공, 약초학 |
| 생활 | 농사, 조련, 건축, 상업 |

- 기술마다 레벨이 있고, 레벨이 오르면 레시피와 도구가 열린다.
- 기술 총합에 상한을 둬서 **한 사람이 모든 걸 최고로 할 수는 없게** 한다 → 다른 플레이어와 거래·협력할 이유가 생김 (멀티플레이일 때 특히 중요).

### 5.3 재료 속성 시스템 ★ 창발성의 핵심
모든 물건은 **속성 태그**를 가진다. 제작과 상호작용은 개별 물건이 아니라 태그로 판단한다.

| 태그 | 규칙 예시 |
|---|---|
| `탈 수 있음` | 불에 닿으면 번진다 → 모닥불, 산불, 적 소굴 태우기 |
| `물에 뜸` | 물 위에 놓을 수 있다 → 다리, 뗏목, 수상 가옥 |
| `단단함` | 벽·도구 재료, 내구도 결정 |
| `보온` | 옷 재료로 쓰면 체온 유지 |
| `먹을 수 있음` / `독` | 요리 재료, 약·독 제작 |

→ 새 아이템을 추가할 때 태그만 붙이면 기존 규칙에 자동으로 맞물린다.

### 5.4 건설
- 칸 단위로 **바닥·벽·문·지붕**을 자유롭게 조합한다 (정해진 건물이 아니라 직접 설계).
- 지붕 아래는 "실내"로 인식 → 비를 막고, 체온 유지, 가구 효과.
- 땅 소유: 정착지에서 부지를 등록해야 내 것이 된다 (멀티플레이 시 남의 집 보호).
- 지형 변경: 땅 파기, 물길 내기, 나무 심기.

### 5.5 동물·공룡
- 야생 생태계: 초식동물 무리, 육식동물 사냥, 번식, 계절 이동.
- 길들이기: 먹이, 신뢰도 → 탈것, 짐 운반, 전투 보조, 가축(알·털·우유).

### 5.6 경제·거래
- NPC 상점은 최소한으로. 가격의 대부분은 **플레이어끼리의 거래**로 정해진다.
- 좌판·가게 건물을 지어 물건을 올려 두면 자리에 없어도 팔린다.
- ❓ 싱글플레이면 NPC 마을 경제로 대체 (6장 결정에 따라 달라짐).

### 5.7 사회
- 마을(부족): 여러 플레이어가 부지를 공유하고, 공동 창고·규칙·마을 이름을 정한다.
- 메시지 게시판, 의뢰(퀘스트)를 플레이어가 직접 올리는 기능.

## 6. ❓ 가장 중요한 결정: 멀티플레이 규모

듀랑고의 자유도는 **"다른 사람들과 함께 만드는 사회"**에서 많이 나온다. 하지만 규모에 따라 개발 난이도가 크게 달라진다.

| 선택지 | 예시 게임 | 자유도·사회성 | 개발·운영 난이도 | 비고 |
|---|---|---|---|---|
| **A. 싱글 + 친구 협동 (2~8명)** | 테라리아, 발헤임, 돈스타브 투게더 | 중 | 중 | 한 사람이 방을 열고 친구가 접속. **서버 비용 없음** |
| **B. 커뮤니티 서버 (수십~100명)** | 마인크래프트 서버, 러스트 | 높음 | 높음 | 유저나 우리가 서버를 띄움. 거래·마을 사회 가능 |
| **C. MMO (수천 명 한 세계)** | 듀랑고, 알비온 온라인 | 매우 높음 | **매우 높음** | 서버 개발·운영팀, 해킹·경제 관리 필요. 듀랑고도 대형 회사가 만들었고 약 1년 반 만에 서비스를 종료함 |

**추천: A로 출시하되, 처음부터 B로 확장할 수 있는 구조로 만든다.**
- 게임 규칙은 항상 "서버"에서 계산하게 짠다. 싱글플레이도 내 컴퓨터 안의 서버에 접속하는 방식이다.
- 이렇게 하면 나중에 전용 서버(B)를 여는 게 "새로 만들기"가 아니라 "기능 추가"가 된다.
- **멀티플레이를 나중에 붙이는 건 거의 다시 만드는 수준이라, 이 결정은 코드를 쓰기 전에 해야 한다.**

## 7. 기술 설계 (Godot 4)

### 7.1 구조 원칙
- **서버 권한 구조:** 모든 행동은 "요청 → 서버 판정 → 결과 전파" 순서로 처리한다 (싱글도 동일).
- **청크 월드:** 맵을 32×32 칸 단위 조각(청크)으로 나눠 가까운 곳만 불러오고 저장한다 → 넓은 월드, 모바일 메모리 대응.
- **절차적 생성:** 시드(seed) 숫자 하나로 탐험 섬을 만든다 (지형 → 생태계 → 자원 배치 순서).
- **데이터 주도:** 아이템, 레시피, 동물, 태그 규칙을 전부 데이터 파일로 관리한다.
- **엔티티 시스템:** 나무·동물·가구·플레이어를 모두 "속성 조합"으로 표현한다 (5.3의 태그와 연결).

### 7.2 폴더 구조 (초안)
```
game/
├─ core/          # 서버 권한 게임 규칙 (화면과 분리)
│   ├─ world/         # 청크, 절차적 생성, 저장
│   ├─ entities/      # 엔티티·속성·태그 규칙
│   ├─ survival/  crafting/  building/  creatures/  economy/
│   └─ net/           # 요청·동기화 (싱글=로컬 서버)
├─ client/        # 화면, 입력, UI, 사운드
├─ data/          # 아이템·레시피·동물·태그 정의
└─ assets/        # 픽셀아트 에셋 팩
```

## 8. 아트
- 에셋 팩 조건: 상업적 이용 허용, 16×16, **지형 종류가 많고**(숲·사막·설원·늪), 동물·몬스터 스프라이트, 건축 부품(벽·지붕·문)이 한 시리즈로 갖춰져 있을 것.
- 공룡처럼 팩에 없는 생물은 외주로 보충 (예산 ❓).

## 9. 로드맵

| 단계 | 목표 | 완료 기준 |
|---|---|---|
| **M0 기술 검증** | 청크 월드 + 서버 권한 구조 + 2인 접속 | 두 명이 같은 세계에서 나무를 베고 벽을 세우는 게 동기화됨 |
| **M1 샌드박스 핵심** | 생존, 채집, 제작, 건설, 태그 규칙 | 1시간 동안 목표 없이 놀아도 재미있는가 |
| **M2 생태계·탐험** | 동물, 길들이기, 절차적 탐험 섬 | 매번 다른 섬에서 새로운 경험 |
| **M3 사회·경제** | 거래, 좌판, 마을 | 친구 4명이 역할을 나눠 마을을 만듦 |
| **M4 얼리 액세스** | Steam 얼리 액세스 출시 | 유저 피드백으로 콘텐츠 확장 |

> 샌드박스 게임은 **얼리 액세스로 먼저 출시해 유저와 함께 키우는 방식**이 잘 맞는다 (테라리아, 림월드, 발헤임 모두 이렇게 성장).
